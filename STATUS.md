## Blocker: SparseFlashAttentionTilingDataMla not defined in package

The kernel entry (`sparse_flash_attention.cpp`) uses:
```cpp
SFA_OP_IMPL(BaseApi::SparseFlashAttentionKernelMla, SparseFlashAttentionTilingDataMla, ...)
```

This macro expands to `GET_TILING_DATA_WITH_STRUCT(...)` which requires the
`SparseFlashAttentionTilingDataMla` struct to be defined. **This struct is NOT
defined in any header file in the custom_cot package** — it is generated by the
CANN TBE build system (`asc_op_compile_base.asc_op_compiler.compile_op`) at
compile time.

### Evidence

1. `grep -rn "SparseFlashAttentionTilingDataMla" custom_cot_impl/` finds only
   *usages* (as parameter types), no struct/class definition.
2. `sparse_flash_attention_template_tiling_key.h` defines tiling template *keys*
   (for variant selection), not the tiling *data struct*.
3. `dynamic/sparse_flash_attention.py` is a TBE build script that calls
   `asc_op_compile_base.asc_op_compiler.compile_op` — the struct is generated
   inside this pipeline.

### TBE build pipeline crash

Running the TBE pipeline (probe_original_sfa.py --compile) crashes with SIGSEGV
(returncode -11). Root cause: `set_current_compile_soc_info('Ascend950DT')`
fails with `Check failed: (get_platform_info_flag == 0) is false: get platform
info failed` — the CANN compile base cannot read NPU hardware info in the c4
container.

Direct `ccec --asc-aicore-lang --npu-arch=dav-3510` gets past the arch check but
fails on:
```
sparse_flash_attention.cpp:88:61: error: use of undeclared identifier 'SparseFlashAttentionTilingDataMla'
```

### What's needed to unblock

Option A: Run the TBE build pipeline in an environment where NPU platform info
is accessible (e.g., the mxllm container or a bare-metal host). This would
generate the tiling struct header.

Option B: Obtain the generated `SparseFlashAttentionTilingDataMla` struct
definition from the CANN build infrastructure (e.g., from a previous build's
intermediate files or from the ops team's build artifacts).

Option C: Reverse-engineer the struct from the compiled binary (.o) and kernel
usage patterns. Risk: ABI mismatch.
